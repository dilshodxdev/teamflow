# Muammolarni boshqarish

Risk — kelajakdagi noaniq hodisa; issue — allaqachon kuzatilgan to‘siq yoki xato. Ularni alohida yozish kerak.

Issue yozuvi: sarlavha, kutilgan va haqiqiy xatti-harakat, qayta yaratish qadamlari, muhit, jiddiylik, mas’ul, qabul mezoni va tekshiruv dalili. Parol, cookie va DB nusxasidagi shaxsiy ma’lumotni ilova qilmang.

| Jiddiylik | Misol                                     | Reaksiya rejasi                          |
| --------- | ----------------------------------------- | ---------------------------------------- |
| Kritik    | Ruxsatsiz yozish yoki ma’lumot yo‘qolishi | Topshirishni to‘xtatish; darhol tuzatish |
| Yuqori    | Kirish yoki asosiy CRUD ishlamaydi        | Shu kuni tuzatish                        |
| O‘rta     | Bitta yordamchi oqim buzilgan             | MVP ta’siri bo‘yicha saralash            |
| Past      | Mayda matn yoki joylashuv                 | Qolgan vaqtga ko‘ra                      |

Oqim: ochish → takrorlash → test → tuzatish → qayta tekshirish → yopish. API shartnomasi o‘zgarishi Gemini va foydalanuvchi bilan kelishiladi. GitHubga joylash uchun draftlar [github-issue-drafts.md](github-issue-drafts.md)da; ular avtomatik chop etilmagan.
