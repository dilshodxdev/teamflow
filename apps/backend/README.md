# TeamFlow backend

Node.js 22.13 or newer is required for `node:sqlite` (Node currently emits an experimental-feature warning). Copy `.env.example` to `.env` in this directory to customize settings. `DATABASE_PATH` is resolved relative to this directory. Startup creates missing tables without resetting an existing database.

From the project root, use `pnpm dev`, `pnpm build`, and `pnpm test`. Run `pnpm db:seed` for optional fictional demonstration data. On first creation generated passwords are saved in the ignored `apps/backend/data/demo-credentials.json` file; keep this file private. For a custom `DATABASE_PATH`, credentials are stored beside the database as `<database-name>.demo-credentials.json` (a database named `teamflow` uses `demo-credentials.json`). The file is created with owner-only permissions where supported; Windows access depends on the containing folder ACL. For a database outside this repository, ensure the file is excluded from any other version control or backups. Alternatively set the demo email and password variables in `apps/backend/.env` first; supplied passwords are not written to the generated credentials file. The seed refuses to overwrite a pre-existing credentials file if it needs to generate new passwords. The seed never resets existing credentials or automatically takes over existing accounts. If an existing account occupies a demo email, select a different demo email for the first seed. Demo records are examples, not verified student contributions.

Registration creates a pending account; a manager explicitly adds or saves a member with the matching email to approve it. Email ownership is not verified. Mutating API requests, including bodyless DELETE and logout, must use `Content-Type: application/json`. Browser origins must match `FRONTEND_URL` or the backend's own origin. Cookies are marked Secure when `NODE_ENV=production`, which requires HTTPS for browser login.
